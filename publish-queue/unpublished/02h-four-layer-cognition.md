# AI Agent 架构缺了一层——知识、记忆、智慧、智能不该被混在一起

**"巴黎是法国首都"和"昨天用户说想吃意面"——这两条信息该被怎么处理？**

如果你是一个 AI Agent 设计者，你可能觉得——都是信息，存一起就好。

这就是当前所有主流 Agent 架构（包括 CoALA 和 LeCun 的 JEPA）在犯的错误。

这个月一篇论文说：**这两条信息的持久性机制，应该在根本上不同。混在一起处理，就是它们一直做不稳健的根源。**

---

## 灾难性混用

想象一下——你的 AI Agent 学了两条信息：

- 事实 1："巴黎是法国首都"
- 事实 2："用户昨天说想吃意面"

现在想象系统采用了"所有记忆按时间衰减"的机制——那么一个月后，"巴黎是法国首都"可能已经被淡忘了。

这显然是错的。**前者是知识（永恒不变），后者是记忆（应当衰减）。**

反过来，如果采用"所有信息直到被更正才替换"的机制——那么用户一年前说"想吃意面"的话，就会一直作为偏好被系统调用。

也是错的。**前者不该衰减，后者应该衰减。**

当前主流 Agent 架构之所以行为经常"奇怪"，根因就是——**它们对所有信息用了同一种持久性机制**。

## 四层分解：每层有根本不同的持久性语义

论文的提议：把 Agent 的"大脑"分成四层，每层有**根本不同的更新规则**。

| 层 | 持久性机制 | 例子 |
|---|---|---|
| **Knowledge**（知识） | 永久，只被取代 | "巴黎是法国首都" |
| **Memory**（记忆） | 艾宾浩斯衰减 | "用户昨天说想吃意面" |
| **Wisdom**（智慧） | 证据门控修正 | "用户不喜欢辣（基于多次观察）" |
| **Intelligence**（智能） | 瞬时，用完即弃 | 当前推理链的中间结果 |

四种更新语义彻底不同：

**取代（supersession）**——这是 Knowledge 层的规则。一条事实一旦进来就永久保留，除非**被一个新事实推翻**。不随时间衰减。"法国首都"不会因为一年没被使用就淡化，只有当它变成"马赛是法国首都"时才被替换。

**艾宾浩斯衰减（decay）**——这是 Memory 层的规则。1885 年艾宾浩斯测量人脑遗忘发现的：记忆强度随时间按指数曲线下降。不被重新激活的记忆会慢慢淡化直到消失。"用户昨天说想吃意面"按这个规则处理——一个月后应该自然失效。

**证据门控（evidence-gated）**——这是 Wisdom 层的规则。一个判断不应该因为一次观察就形成或改变，需要**累积足够的证据**。你第一次听用户说"辣的不行"时，可能只是当天心情不好；听过十次后，"不喜欢辣"就可以作为判断写入。更新有一个证据阈值。

**瞬时（ephemeral）**——这是 Intelligence 层的规则。当前推理中产生的中间结果（"如果 A 成立那 B 也成立"）只在这一次思考过程中有意义，推理链结束后**立刻清空**。不持久，也不该持久。

这不是"长期记忆 vs 短期记忆"的老二分法——**这是四个独立的更新语义，每个用在错位置都会出问题。**

## 8 个独立的失败案例都指向同一个根

论文做了一件很聪明的事——找了 8 个看似无关的 Agent 系统失败案例：

- Karpathy 提到的 LLM Knowledge Base 不能稳定处理事实矛盾
- BEAM benchmark 的矛盾解决分数接近零
- 长对话中 AI 会"忘记"基础事实
- RAG 检索到过时信息不知该不该信
- Agent 对一个用户偏好从一次提及就过度泛化
- 短对话推理过程中的中间结论被错误地写入长期状态
- ……

**每一个现象都在暴露同一个根问题——系统没有区分这四种持久性语义。**

这让一个看起来抽象的架构论文突然有了实际意义：如果你的 Agent 在这些地方翻车，不是 prompt 调不对、也不是模型不够大，是**架构没给信息分类**。

## 和个人知识管理的对应

这个四层分解，和你整理个人知识的经验也惊人地对应：

- **Knowledge**：已确认的事实、学过的原理（笔记里的"确信 - 不再迭代"部分）
- **Memory**：具体发生过的事、临时遇到的信息（日记、临时记录）
- **Wisdom**：多次观察形成的判断、经验（思考文件、经年积累的理解）
- **Intelligence**：当前在想的问题、草稿（工作台、临时 buffer）

好的笔记系统从直觉上就知道要分开这四种——事实放在一个地方永久保留，每天的日记自然会褪色，经验需要沉淀验证，草稿用完就清掉。

但 AI Agent 一直在用一个机制处理所有。**直到这篇论文把这个直觉写成了数学**——每层有精确的更新规则，不是笼统的"记忆管理"。

## 对 Agent 设计的落地指引

如果你在设计 Agent 系统，这篇给了一张清晰的审查表。

对每个"信息项"问四个问题：

1. 它该被永久保存直到被新事实取代，还是该随时间衰减？
2. 它该在第一次观察后就被相信，还是需要多次证据？
3. 它该持续到会话结束，还是随推理链结束而消失？
4. 它的更新规则是"替换"、"衰减"、"累积证据"，还是"清空"？

如果你的系统没办法在这四个维度上做区分——**你的系统只有一种持久性，只能正确处理一种信息**。

---

AI Agent 的瓶颈，可能不在模型有多大。

**在于它能不能区分自己在处理什么类型的信息。**

"记忆"这个词在人类语言里本来就是模糊的——我们同时用它指事实、经历、判断、当前思考。AI 继承了这种模糊性，然后在这个模糊性上翻车。

这篇论文第一次把这个模糊性拆开了，每一层给了自己的数学。
