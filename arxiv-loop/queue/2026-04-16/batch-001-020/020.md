# 不检索数据，检索"思考"——AI 通过积累思考过程实现自我进化

> ⬜ 待审核 | 品味命中：有趣思路 | 方向：A（AI/Agent）+ B（理解力）

## 简单说

现在的 AI 检索系统是这样的：用户问问题 → 去数据库里找相关的原始文本 → 塞给 AI 让它回答。问题是文本太多塞不进上下文。Thought-Retriever 换了个思路：不检索原始数据，检索 AI **过去回答类似问题时产生的思考过程**。每次 AI 解决一个问题后，它的推理过程会被存储、过滤、组织成"思考记忆"。下次碰到新问题，先查有没有相关的"过去的思考"可以复用。结果：F1 提升至少 7.6%，胜率提升 16%。更惊人的是：AI 处理的问题越多，记忆越丰富，回答越好——它在真正地自我进化。

## 原文摘要

We propose Thought-Retriever, a novel model-agnostic algorithm that helps LLMs generate output conditioned on arbitrarily long external data, without being constrained by the context length or number of retrieved data chunks. Our key insight is to let an LLM fully leverage its intermediate responses generated when solving past user queries (thoughts). This effectively equips LLM-based agents with a self-evolving long-term memory that grows more capable through continuous interaction. Thought-Retriever can indeed help LLM self-evolve after solving more user queries; Thought-Retriever learns to leverage deeper thoughts to answer more abstract user queries.

## 核心内容

### 和传统 RAG 的区别

| | 传统 RAG | Thought-Retriever |
|--|---------|-------------------|
| 检索什么 | 原始文本片段 | AI 过去的推理过程 |
| 受限于 | 上下文长度（塞不下太多） | 不受限（思考已经被压缩过） |
| 随时间 | 不变 | **越用越好**（积累更多思考） |

### 关键发现

1. F1 提升至少 +7.6%，胜率 +16%
2. **自我进化**：处理的问题越多 → 思考记忆越丰富 → 回答越好
3. **深层思考调用**：越抽象的问题，模型越倾向于调用更深层的历史思考
4. 模型无关——可以即插即用在任何 LLM 上

### 核心论断

AI 的长期记忆不应该存"数据"，应该存"思考"。数据是外部的、被动的；思考是内部的、已经被加工过的。存思考 = 存已经消化过的知识。

## AI 分析

### 为什么值得关注

**差异化**：RAG 的所有改进都在"怎么找到更好的原始文本"。这篇说：根本方向错了——不该找原始文本，该找 AI 过去的思考。从"检索数据"到"检索思考"是范式的改变。

**独特性**："越用越好"的自我进化是 Agent 系统的圣杯之一。大部分 Agent 每次从零开始，Thought-Retriever 让 Agent 真正"成长"。

**贡献度**：
- 对 Agent 架构：给长期记忆系统指出了新方向——存思考而非存数据
- 对 content-loop：我们的循环也在积累"思考"（queue 里的 AI 分析），这些分析本身可以被后续循环复用
- 和 queue 009（双轨记忆）呼应：场景轨 ≈ 思考记忆，事实轨 ≈ 原始数据。两篇从不同角度得出了"记忆需要加工"的同一结论
