# 7B 模型做"上下文策展员"，效果达到 GPT-4o 级别，token 省 8 倍

> ⬜ 待审核 | 品味命中：有趣思路 | 方向：A（AI/Agent）

## 简单说

AI 做长链任务时会被越来越长的对话历史淹没——重要信息被噪声掩盖，推理质量下降。这篇的解法是"分工"：一个小模型（7B）专门负责筛选和压缩上下文（ContextCurator），一个大模型只看精选后的内容做推理（TaskExecutor）。7B 的策展员通过强化学习训练，学会了"什么该留什么该删"。结果在 DeepSearch 上 token 消耗降低 8 倍，成功率反而提高。一个 7B 模型的上下文管理能力匹配 GPT-4o。

## 核心数据

- WebArena：成功率 36.4% → 41.2%，token 降 8.8%
- DeepSearch：成功率 53.9% → 57.1%，token 降 **8 倍**（47.4K → ~6K）
- 7B ContextCurator ≈ GPT-4o 的上下文管理能力

---

## AI 分析

**差异化**：不是"更大的上下文窗口"，是"更聪明的上下文筛选"。和 queue 005（多 Agent 传更少信息反而更好）同一逻辑。

**贡献度**：小模型做策展 + 大模型做推理的分工模式可能是 Agent 架构的通用范式。
