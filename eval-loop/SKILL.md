# 评估循环

> 独立于扫描循环运行。扫描往 queue/ 填素材，评估从 queue/ 选素材并生成终稿。
> 这是从素材到可发布物的完整闭环。

## 规则文件

评估时**必须**加载以下两个文件作为评分依据：
- `../arxiv-loop/eval.md` — 通用评估规则（三维度 + 门槛 + 排序）
- `../arxiv-loop/config.md` — 个人偏好加权（方向匹配度）

## 每轮执行

### 1. 收集待评估素材

扫描 queue 目录中标记为 `⬜ 待审核` 的文件：
```
D:/Projects/content-loop/arxiv-loop/queue/**/*.md
```
排除 INDEX.md。

如果没有待审核文件 → 输出"本轮无新素材"，结束。

### 2. 逐篇评估打分

对每篇待审核素材，读取全文后按 eval.md **四维度**打分（2026-04-22 加入可信度）：

```
认知冲击 (0-3) × 3
吸引力   (0-3) × 2
通俗可转化性 (0-2) × 1
学术可信度 (0-3) × 1  ★ 新增，使用 queue 文件"权威信号"字段
─────────────────────
通用分 (满分 20)

+ config.md 偏好加权
─────────────────────
总分
```

**学术可信度优先从 queue 文件的"## 权威信号"字段取**。如果 arxiv-loop 没有采集（旧素材或 API 失败），评估者需要：
- 快速调用 Semantic Scholar API（见 arxiv-loop SKILL.md step 5.5）
- 或基于 PDF 首页机构信息+查作者 Google Scholar 给出估算分

去重检查（和 `publish-queue/` 下已有内容比对）：
- 同一篇论文已有终稿 → 跳过
- 同话题已有类似角度 → 总分 -2

### 3. 判定 + 生成终稿

按 eval.md 门槛判定（2026-04-22 起门槛上调因为加入可信度维）：

| 总分 | 判定 | 动作 |
|------|------|------|
| ≥22 | 必发 | 生成终稿 → `publish-queue/unpublished/` |
| 17-21 | 优先发 | 生成终稿 → `publish-queue/unpublished/` |
| 12-16 | 备选 | 保持 `⬜ 待审核`，下轮继续 |
| <12 | 淘汰 | 标记 `❌ 未通过评估` |

**对 ≥15 的素材，当轮立即生成终稿：**

### 3.0 写稿前必须做：拉论文原文

**必须先 WebFetch 论文原文**（arxiv html、mdpi 版本、或官方 PDF），拿到核心机制的公式/算法/数据。

queue 里的素材摘要是科普档级别的信息，**只能用于筛选和评分，不能作为写稿的主要来源**——拿二手摘要写不出精读档。

如果 WebFetch 失败（403/404/网络问题）：
- 跳过这篇
- queue 文件标记 `⚠️ 待原文`
- 本轮不生成终稿

### 3.1 写稿

终稿定位：**叙事式机制讲解**。

核心标准：读完读者能**用自己的话给朋友解释清楚论文的核心机制**——不是「大概知道有这么个东西」（科普档失败），也不是「抱着论文符号原样背」（形式堆砌失败）。**用中文叙事把机制讲透**，让读者真的懂了。

### 核心要求

1. **机制必须说清，用中文讲为主**
   - 抽象概念都要让读者明白「具体怎么工作」
   - **公式/伪代码/字母符号是最后选项**——只在中文真说不清、符号比中文更省事时才用
   - 中文能讲清的，坚决用中文讲
   - 反例：给「闭包保真度」写 `F_Cn = |Cn(S) ∩ Cn(Ŝ)| / |Cn(S) ∪ Cn(Ŝ)|`
   - 正例：中文讲「两边能推出的结论集合要完全一样」
   - 反例：给「不可约核」写伪代码
   - 正例：中文讲「逐个检查每条事实，能从其他条推出来的就删」

2. **至少一个读者能跟着算一遍的例子**
   - **用通俗场景和小数字**，不是论文原始实验参数
   - 读者能在脑子里自己推一遍
   - 反例：`Λ₁ = log|S_O| / log|Atom(S_O)| ≈ 1.58`
   - 正例：「苏格拉底三段论有 3 条事实，但只需要传前 2 条——第 3 条自动推出，省了 1/3 带宽」

3. **推导链用叙事讲**
   - 讲「为什么这个结论能成立」
   - 禁止写「Theorem 4.1」+「证明三步：1. ... 2. ... 3. ...」这种论文骨架
   - 让逻辑自然流淌
   - 反例：独立小节「核心定理：R_sem(0) = P_A·H(π_A)」+「证明三步」
   - 正例：叙事讲「数学证明了：传语义知识的最小成本就等于只传不可约核的那一部分；冗余事实的传输成本严格为零」

4. **每段必须有一个可读性锚点**
   - 金句 / 比喻 / 具体场景 / 对比——任选一种，每段都要有
   - 不能连续两段都是纯机制描述
   - 可读性锚点 ≠ 抛开机制讲故事，而是把机制用有画面感的方式讲

### 可读性形式要求

- 强 Hook 开头
- 短段落，每段一个点
- 核心结论用加粗
- 结尾点明「为什么重要」

### 反模式（评估时发现任一条必须退回重写）

**失败模式 A：信息浓度不足（科普档失败）**
- 通篇概念 + 类比，没有一个能算的例子
- 抽象概念没讲清「具体怎么工作」
- 说「这是数学同构」但不说同构在哪
- 用「大概」「某种程度上」「类似于」糊弄核心机制

**失败模式 B：形式堆砌（论文档失败）**
- 公式 / 伪代码 / 字母符号出现超过 3 次
- 且这些符号不是「比中文更省事」，而是「把论文原话搬过来」
- 段落机械分成「核心定理」「证明三步」「应用」这种论文骨架
- 每段开头用加粗技术术语（「**闭包保真度**」「**不可约核**」「**语义杠杆因子**」）当名词锚，堆成术语清单
- 读起来像论文导读，不像中文文章

**两种模式都是失败**——目标是「用中文讲故事的方式把机制讲清」，在科普档和论文档之间找中间。

### 字数

**1500-2500 字**——给中文叙事留呼吸空间，机制讲清不能压缩，可读性段落也要够

### 3.9 写完必须自检

对着刚写完的稿件，依次过一遍检查清单：

1. **标题**：是不是一句有冲击力的完整判断句？（反例：「关于 XX 的研究」「YY 综述」）
2. **公式/字母符号**：是否 ≤ 3 次？
3. **论文骨架**：有没有「核心定理」「证明三步」「应用」这种机械分节？
4. **术语清单**：每段开头是不是用加粗技术术语当名词锚？
5. **可读性锚点**：每段是否有金句 / 比喻 / 具体场景 / 对比 任一种？
6. **复述测试**：一个朋友读完，他能用自己的话复述核心机制吗？

**任何一条过不去，删稿重写，不要修补**——修补只会变成「半科普半论文」的四不像。

终稿文件格式：
```markdown
# [标题：一句话 Hook]

[正文]

---

> 论文：[标题]
> 链接：[URL]
> 评估分：[总分] = 冲击[X]×3 + 吸引[X]×2 + 通俗[X]×1 + 偏好[X]
```

**不要包含「来源素材」字段**（内部 queue 路径不应出现在发布稿件里）。

文件命名：`{排名序号}-{关键词}.md`
- 两位数前缀：`01` = 最高分，`02` = 第二高
- 文件管理器按名称排序 = 优先级从高到低
- 增量评估时：新终稿插入现有排序，重新编号

### 4. 更新状态

更新 queue 文件标记：
- 生成终稿的：`⬜ 待审核` → `✅ 已通过评估`
- 重复选题的：`⬜ 待审核` → `✅ 已通过评估 (重复)`
- 淘汰的：`⬜ 待审核` → `❌ 未通过评估`

同步维护 `queue/INDEX.md`：

**按分数分流**：

- **≥15（必发/优先发）**：从"待审核"表删除，插入"已通过评估"表。位置按评分降序；同分时按批次新→旧、编号大→小。行格式：`| {评分} | {批次} | {#} | {标题} | {品味} | {产出序号} |`（产出序号未生成终稿时写 `—`）
- **11-14（备选）**：**保留在"待审核"表**，但将该行的评分列从 `—` 更新为实际分数（例如 `12`）
- **<11（淘汰）**：从"待审核"表直接删除
- **重复**：从"待审核"表删除，插入"已评估（重复）"表，行格式：`| {批次} | {#} | {标题} | {对应已有文件} |`

**重排"待审核"表**（每轮评估结束时必做）：

整个"待审核"表按**评分降序**重排：
- 评分列有实际分数的行（11-14 分备选）排在**顶部**，按分数从高到低
- 评分列为 `—` 的未评行排在**底部**，内部按批次新→旧、编号大→小
- 同评分时按批次新→旧 tiebreak

目的：用户打开 INDEX.md 一眼看到"接下来最值得关注的素材"在顶部。

更新 `state.json`。

### 5. 输出摘要

每轮结束输出一行摘要：
```
评估 R{N}：{X} 篇待审 → {Y} 篇生成终稿 / {Z} 篇备选 / {W} 篇淘汰
```

## 终止条件

- 本轮所有待审核文件处理完毕即结束
- 不以通过数量为目标——没有好素材就不生成

## Loop 触发

```
/loop 3m 执行 D:/Projects/content-loop/eval-loop/SKILL.md 中定义的一轮评估循环
```

每 3 分钟一轮。每轮只处理 `⬜ 待审核` 的文件，已评估的自动跳过。
无新素材则直接结束，不消耗 token。
